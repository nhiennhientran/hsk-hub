## Exact asset and path handling

`package-unified.mjs` validates 357 original MP3 files against the existing HSK1 and HSK2/3 SHA/byte manifests, every licensed handwriting JSON against its provenance manifest, all 150 current reviewed HSK1 original PNG crops against the 15 current source catalogues (including `lesson-04-current.json`), and all 438 auxiliary SVGs against the 33 approved `illustrationManifest` entries and their `assetSha256`. Arbitrary page PNGs, SVGs, books, archives, source maps, private documents and backend directories are rejected.

HSK1 source activity images resolve relative to the document, while textbook originals, audio, word-card resources and handwriting resolve via `asset-base`. All seven unified entry directories can select HSK1 through explicit hash routes. Each receives the same 150 SHA-verified activity crops, while `course-engine` contains the shared master assets. This increases path count, but does not invent new images or treat the 48 textbook-gallery uses as 48 additional unique images. Repeated Git blob contents can be reused when saving the eventual package.

The entry HTML sets each course's default level and shared asset base. The current unified application deliberately supports explicit cross-level query/hash navigation. It does not implement the older package's `hsk-level-locked` behavior. Its root portal has three unified course cards plus links to HSK4 and old courses; this differs from the historical five-card portal. The original `tests/packaged/entries.spec.ts` is unchanged. New package-specific tests exercise the real unified consumer behavior, and the separate legacy worker tests the retained old student hosts.
