# 音频专项接续复核（2026-10-04）

本轮检查基于恢复的 `0ad4732` 及主集成随后提供的两次小范围修复。审查范围为实际共享播放器的初次播放状态、音频文件完整性、片段来源绑定和已有待核验边界。本专项未修改共享播放器、课程数据或部署设置；复现脚本与结果均在本目录。

## 本轮完成

- 重新核对全部 **357 个 MP3** 的 SHA256 和文件字节数：HSK1 93 个，HSK2/3 264 个，全部与清单相符。
- 重新解码所有 **32 个**已批准精细片段所依赖的原始音轨；ffmpeg 无错误。按既有证据采用 16 kHz 单声道 PCM，32 个解码时长和容器时长均匹配。
- 当前课程 JSON 与来源授权表的 **74 条词汇、78 条课文行**一致；其 **95 个源文本句子**可重建原行。
- 运行音频播放器及片段契约测试：原始代码 **57/57**；主集成补充三个回归测试后的候选 **60/60**。
- 另运行 HSK1 音频来源、原轨道及无音频记录有关的定向测试 **14/14**。
- 独立运行 **8 个整轨保留探针**：显式/隐式 start=0，分别配合 NaN/Infinity/0/有效 duration；正常原轨播放及既有零时长恢复逻辑均保留。

## 已复现并闭合的两项缺口

1. `0ad4732` 中，有限片段起播时 duration=NaN 或 Infinity，仍可经过 native playing/seeked 将静音关闭并报告播放成功。初次定位只拦截 duration===0，未要求有限正时长。主集成修复后，两种情况均维持 loading/静音，待有效元数据后再处理。
2. 第一修订仍存在元数据在定位途中无 durationchange 地缩短的问题：最初 duration=16.296，定位时变为5或0.5，仍会宣布播放0.718—9.825。第二修订在第一次取消静音前再次检查当前位置对应的完整范围；现已分别以“录音过短”及“起点越界”失败，并保持静音。原有0.05秒 MP3 容器误差容忍保留。

上述均是对实际 service 的独立受控复现，不能称为用户曾实际听到错误音频。历史浏览器问题是另一个已有证据：3-7.mp3 请求0.718起播，seeked 暴露0.003951848且非静音。0ad4732的静音定位修复及本轮加强，仍须由集成方完成原生浏览器验证。
