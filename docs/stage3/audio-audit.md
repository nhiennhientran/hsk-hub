## 原RAR与网站音轨的完整比较

原始解压目录为工作区`tmp/pdfs/materials_audit/audio/`；网站音轨位于`new-hsk1/hsk1/audio/`。两处均有93个同名MP3：第1–3课各7条，第4–15课各6条；其中45条课文、45条生词、3条前期绕口令。没有缺失同名文件或额外网站音轨。

| 检查项 | 结果 | 能说明什么 |
|---|---:|---|
| 同名文件 | 93 / 93 | 文件课号对应完整。 |
| 完整文件字节相同 | 0 / 93 | 容器／标签不同，不能只用全文件SHA判定声音变化。 |
| 实际MP3音频包逐包SHA相同 | 93 / 93 | 网站版保留了原RAR的编码声音数据，未换成TTS或另行录音。 |
| 原音去掉开头529个采样后，与网站版解码PCM逐样本相同 | 93 / 93 | 两版在统一时间轴后的波形完全相同；最大样本差为0。 |
| 采样率／声道 | 44,100 Hz / 双声道 | 比较使用原生采样率和声道，未靠重采样掩盖差异。 |
| 原文件总大小 | 44,216,448字节 | 包含封面等标签。 |

原文件含180,131字节ID3标签及封面；网站版去掉大标签并加入MP3 Info头。以`1-1.mp3`为例，两版244个实际音频包的SHA序列相同；网站版首包的解码提示包含`skip_samples: 529`。全93条均表现为相同的529采样差。

不能直接相减`ffprobe`的容器时长来推导声音偏移。两版容器报告时长的差在0.004168–0.069334秒之间，但解码采样的差统一为529个。相关边界应依据实际解码时间轴。

### 时间码换算

既有`_audio-work`时间码针对网站版音轨。按本次FFmpeg解码结果：

```text
offset = 529 / 44100 = 0.01199546485260771 秒
原RAR解码时间 = 网站版解码时间 + offset
```

直接复用网站版音轨时沿用网站时间码；若从原RAR解码素材生成片段，应给同一内容的起止点都增加该偏移。时间码须在最终播放器里实测，尤其不能把FFmpeg的解码结果直接当作所有浏览器对MP3头信息处理均一致的证明。

终稿的`timingBasis: original-pcm-asr-waveform-reviewed`是审查方法标签；`start/end`数值仍为网站版解码PCM秒数，不表示已经切换到原RAR的时间轴。媒体清单同时记录原RAR文件SHA和529采样换算关系。

输入为`_audio-work/all-text-1-15-compact.json`和`all-vocab-1-15-compact.json`，两者版本均为`20260818-step8-v1`。文件里原有“perceptual”或“PASS”字样只代表旧记录，不自动成为本步听审结论。

| 类别 | 音轨数 | 区间数 | 本步处理 |
|---|---:|---:|---|
| 课文 | 45 | 202 | 作为可供选择的候选句段；不默认一段恰好一个完整话轮。 |
| 生词 | 45 | 330 | 作为对应教材词序的候选区间；词形／多读音须保留具体课次。 |

另将45条生词轨的全部330个候选标签，逐轨与第一步基于原PDF建立的`vocabulary_in_printed_order`比较，词形和顺序全部一致。这证明标签与教材映射相符，不证明每个时间切口内已经听辨到该标签；后者仍需音频内容核对。

技术筛查结果：532段均满足起点不小于0、终点晚于起点、终点不超过网站版解码长度。215段与前一段重叠，反映原区间含起音余量，不能简单首尾拼接。以切口前后各20毫秒RMS均高于−35dBFS为“连续强声切口”筛查条件，没有区间被该规则标记。

这个阈值结果只能排查一类明显风险。低能量辅音、气声、轻声、相邻词残留、语句含义、否定词和数字是否完整，都不能由该阈值自动保证。所有课文轨道首段起点之前的能量均不足全轨能量的0.1%，因此没有发现大量前置声音被排除的技术信号；这仍不是对实际语音内容的听辨结论。

## 最终片段的复用、裁切与实际核查

网站现有93条MP3已被证明保留原RAR真实声音，实际作为派生片段的来源。最终题库记录题目ID、课次、教材印刷/PDF页、音轨文件、时间轴、起止秒数、预期中文文本、越语选项与唯一正确项；媒体清单记录源文件和裁片SHA。边界审查将技术筛查、自动识别、助手内容审阅与没有发生的直接听辨分开记录。

裁切应从解码PCM按采样边界完成，保留自然的起音和收尾余量；默认可从目标语音前约150–250毫秒、后约200–350毫秒的安静区开始考虑，再依据实际邻句调整。不要机械向两端扩展固定时长，因为现有215段存在重叠，扩展可能混入邻句。不要使用`-c copy`直接截MP3作为精确词句片段：MP3帧边界和解码状态会影响实际起音。

实际由`tools/build-stage3-media.py`从解码声音裁切，重新编码为24kHz单声道、48kbps MP3，合计405个播放记录：75听力题及330有音词卡。未使用MP3包复制裁切。最终浏览器播放的是独立片段，保留裁切前后来源对应、实际文件SHA及解码时长；不依赖低频`timeupdate`事件在整轨中精确截停短词。

慢速和倍速应保留正常音高；HTML媒体元素可显式启用`preservesPitch`，在最终支持浏览器中验证数据契约的0.65×、0.75×、1×、1.25×、1.5×五档。纯Web Audio改变`playbackRate`默认会一起改变音高，不能把这种变调作为自然语言慢速听力体验交付。

原轨ASR run `36812857427`覆盖90条，首轮裁片ASR run `36814798294`覆盖405条；29片段medium复核 run `36816487307`绑定修订后的真实声音，均未给模型预期教材文本。最终405条中376绑定首轮结果、29绑定二次结果，哈希全部相符。声源不会因为识别结果写成同音字而替换教材原文。

首轮识别揭示7-6的“里”、9-2的“边”、9-4的“上”有多读音发声，旧候选少分配了这些声音，导致医院实际播晚上、本实际播上、学习混入第等错位。已统一改16词卡并同步医院听力。此前另有5道句/对话的片段选择或边界调整，因此初选至终稿共22条区间变更（6听力、16词卡）。谁、里、边、上的当前片段各含4发声块；那个含2块，不能据汉字转写承诺两种读法都已辨清。所有变更前后与原始识别记录均保留。

最终浏览器 run `36816487219`的原始记录已经读取：Chromium 151.0.7922.34，35项检查通过，102条真实播放记录覆盖75道听力、五档速度、暂停恢复和失败重试。其中101条附SHA，均与最终媒体清单一致；另1条为同一已识别片段的中途改速事件。实际播放、速度进度及保调配置不是人耳音质证明，也不代表Safari或实体手机已测试。

## 证据文件与未核查项

正式来源清单为[audio-source-manifest.json](audio-source-manifest.json)，逐轨记录原文件／网站文件SHA、实际音频包序列SHA、采样数、529采样偏移和对齐PCM哈希。可复现脚本为[stage3-audio-audit.py](../../tools/stage3-audio-audit.py)，只依赖Python标准库以及FFmpeg／FFprobe，不需要语音识别模型；它不会修改输入音频。

从仓库根目录可用以下命令重跑（`--source-dir`应指向实际RAR解压目录）：

```sh
python tools/stage3-audio-audit.py \
  --source-dir ../tmp/pdfs/materials_audit/audio \
  --manifest docs/stage3/audio-source-manifest.json \
  --full-report ../tmp/stage3-audio-audit/source-site-comparison-final.json
```

本次使用FFmpeg／FFprobe 6.1.1-3ubuntu5。原音与网站PCM逐字节一致的比较是在同一解码器版本内完成；不同浏览器的实际播放仍单独验证。

本步完整中间核对材料位于工作区`tmp/stage3-audio-audit/`：

- `source-site-comparison.json`：93条逐文件SHA、实际音频包序列SHA、采样数、偏移及PCM相等结果。
- `source-site-comparison-final.json`：正式审计脚本的完整结果，另保留两版原始／对齐PCM哈希及MP3首包解码提示。
- `compare_audio.py`：首次探索性来源／PCM比较程序；正式复验使用仓库内的标准库版本。
- `candidate-boundary-screen.json`：532段起止范围、重叠和切口前后RMS。
- `check_candidate_boundaries.py`：上述区间技术筛查程序。
